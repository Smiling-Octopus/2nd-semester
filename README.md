# Windows 환경에서 PDF를 활용한 공격자 정보 수집 및 위협 대응 기법

배재대학교 소프트웨어공학부(정보보안학)의 산학캡스톤디자인2 팀 **웃는 문어**의 프로젝트 저장소입니다.

## 프로젝트 개요

침해사고 대응 과정에서 피해 시스템의 로그와 이미 알려진 위협 정보만으로는 공격자 측의 시스템 및 통신 정보를 충분히 확보하기 어렵습니다. 이 프로젝트는 통제된 테스트베드에서 PDF 열람을 계기로 동작하는 정보 수집 프로그램과 분석 서버를 구성하고, 수집 정보의 분석 및 위협 대응 연계 가능성을 검증하는 것을 목표로 합니다.

수집된 정보는 분석 서버에서 통합 관리하며, IP 위치정보, ASN, 프로세스와 통신 대상의 관계를 분석·시각화하는 방안을 검토합니다. 프로젝트 결과는 구현 결과와 실험 결과를 구분하여 기록하고, 환경별 제약사항과 해석상의 한계를 함께 정리합니다.

> 본 프로젝트의 모든 구현과 실험은 VirtualBox 테스트베드에서만 수행합니다. 실제 시스템, 제3자 문서 또는 운영 중인 네트워크를 대상으로 사용하지 않습니다.

## 현재 상태

프로젝트 수행 전 단계입니다. 초기 설계와 요구사항을 정리한 뒤 개발 환경을 구축하고, 수집 프로그램·서버·분석 기능을 단계적으로 구현할 예정입니다.

## 저장소 구조

프로젝트 관련 코드는 기능에 따라 다음 세 디렉터리로 구분합니다.

```text
2nd-semester/
├─ System Information Gathering/  # Windows 시스템 정보 수집 프로그램
├─ PDF File Script Code/           # PDF 파일 및 스크립트 연계 코드
├─ Server/                         # Linux 정보 수집·분석 서버
└─ README.md
```

각 디렉터리의 역할은 다음과 같습니다.

| 디렉터리 | 역할 |
| --- | --- |
| `System Information Gathering` | Windows 환경에서 시스템, 프로세스 및 통신 정보를 수집하는 프로그램 개발 |
| `PDF File Script Code` | 통제된 테스트용 PDF와 PDF 연계 스크립트 코드 관리 |
| `Server` | Linux 환경에서 수집 정보의 수신, 저장, 분석 및 시각화 기능 개발 |

## GitHub 협업 개발 규칙

팀의 효율적인 협업과 코드 품질 유지를 위해 GitHub를 활용한 개발 규칙을 적용합니다. 모든 팀원은 다음 규칙을 준수하여 일관된 협업 환경을 유지합니다.

### Git 상태 및 브랜치 확인

현재 브랜치를 확인합니다.

```powershell
git branch --show-current
```

현재 브랜치의 변경 상태를 함께 확인합니다.

```powershell
git status
```

로컬 및 원격을 포함한 전체 브랜치를 확인합니다.

```powershell
git branch -a
```

### 브랜치 전략

GitLab Flow 방식을 참고하여 다음과 같이 브랜치를 운영합니다.

- `main` 또는 `master`: 항상 배포 가능한 안정적인 코드를 유지합니다. 직접 커밋하지 않습니다.
- `develop`: 다음 릴리즈를 위해 개발 중인 최신 코드를 통합합니다.
- `feature/<이름>/<기능명>`: `develop`에서 생성하여 개별 기능을 개발합니다.

> **주의:** 전반적인 기능 구현과 개발은 `develop` 브랜치를 기준으로 진행합니다. `main` 브랜치에는 섣불리 직접 커밋하거나 푸시하지 않습니다. 작업 완료 후 코드 리뷰와 Pull Request를 거쳐 검증된 변경 사항만 `main`에 반영합니다.

> 브랜치, 커밋 또는 푸시 방법을 모르거나 개발 중 헷갈리는 사항 또는 모르는 사항이 있는 경우에는 `서영석`에게 문의해 주시면 감사하겠습니다.

### 개발 워크플로우

#### 1. 클론

개발을 시작하기 전에 원격 저장소를 로컬에 클론합니다.

```powershell
git clone <레포지토리 URL>
```

#### 2. 동기화

작업을 시작하기 전에 `develop` 브랜치로 이동하고 최신 변경 사항을 가져옵니다.

```powershell
git checkout develop
git pull origin develop
```

`origin`은 원격 저장소의 기본 이름입니다. 원격 저장소에 등록된 이름과 주소는 다음 명령어로 확인할 수 있습니다.

```powershell
git remote -v
```

#### 3. 브랜치 생성

새로운 기능 개발 또는 버그 수정을 위해 `develop` 브랜치에서 작업 브랜치를 생성합니다.

```powershell
git checkout -b feature/<이름>/<기능명>
```

예시:

```powershell
git checkout -b feature/홍길동/Windows
```

#### 4. 개발

생성한 작업 브랜치와 담당 폴더에서 코드를 작성하고 변경합니다.

#### 5. 커밋

변경 사항을 논리적인 단위로 나누어 커밋합니다. 커밋 메시지는 코딩 컨벤션에 정의된 형식을 사용합니다.

```powershell
git add .
git commit -m "이름 : 작업 내용"
```

#### 6. 푸시

로컬 작업 브랜치의 커밋을 원격 저장소에 업로드합니다.

```powershell
git push origin feature/<이름>/<기능명>
```

예시:

```powershell
git push origin feature/홍길동/Windows
```

#### 7. Pull Request

작업이 완료되면 GitHub에서 작업 브랜치에서 `develop`으로 Pull Request를 생성합니다. 팀원의 코드 리뷰와 확인이 완료된 후 `develop`에 병합합니다. `develop`의 안정성이 확인되면 `main`에 병합합니다.
