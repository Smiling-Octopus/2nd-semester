# 김종윤 — PDF 검토 5주차 진행 요약

2026-10-13의 Qwen 초안 반영과 2026-10-23의 Windows 실험·분석 기록을 **작업 순서에 따라 5개 주차로 재구성**했습니다. 실제 5주에 걸친 수행 날짜를 의미하지 않으며, 각 주차는 3줄입니다. 근거와 한계는 [Windows 후속 검증](WINDOWS_VALIDATION_20261023.md)을 따릅니다.

## 1주차: 기존 코드 분석 및 실험 환경 점검

- PDF 생성기와 Flask 수신 서버의 구조 및 요청 기록 방식을 분석하였다.
- Windows Chrome·Edge에서 원본 PDF와 정상 대조군의 표시 상태를 비교하였다.
- PDF 내부 구조 오류, 한글 깨짐, 외부 이미지 요청이 발생하지 않는 문제를 확인하였다.

## 2주차: PDF 오류 수정 및 기본 기능 검증

- 별도 작업공간에서 PDF 저장 구조를 수정하고 한글 글꼴을 내장하여 표시 오류를 개선하였다.
- Chrome·Edge에서 정상 표시와 명시적 링크 클릭에 따른 서버 수신을 확인하였다.
- 수정 대조군의 구조·파일 보존·수신 로그 테스트 3개를 통과하고, 자동 전송 목표와 구분하였다.

## 3주차: 자동 전송 및 외부 이미지 동작 실험

- 서버에서 제공한 PDF와 로컬 PDF를 대상으로 JavaScript 실행과 자동 전송 여부를 비교하였다.
- 문서 열림 스크립트는 실행되지만 자동 폼 전송에는 사용자 동작이 요구됨을 확인하였다.
- Chrome·Edge의 네 가지 조건에서 외부 이미지 요청을 시험했으며, 자동 요청은 관측되지 않았다.

## 4주차: 추가 PDF 기능 검토 및 Windows 실증

- ARTEX를 활용해 공식 구현을 검토하고 추가 시험할 PDF 액션과 외부 참조 후보를 선정하였다.
- 일반 브라우저 창에서 URI·폼 액션, 외부 문서 참조, XFA 이미지 등을 시험하였다.
- 시험 범위에서 자동 요청은 관측되지 않았으며, XFA는 기준 화면이 표시되지 않아 처리 여부를 확정하지 않았다.

## 5주차: 바이너리 분석 및 결과 종합

- Windows에 REA·Ghidra 분석 환경을 구축하고 Chrome DLL의 관련 함수와 입력 조건을 분석하였다.
- 다운로드한 PDF를 일반 Chrome 창에서 입력 없이 약 60초간 관측하여 자동 요청이 없음을 재확인하였다.
- 소스·화면·로그·분석 근거를 보존하고, PDF 열람만으로 자동 전송하는 원래 목표는 미달성으로 정리하였다.
